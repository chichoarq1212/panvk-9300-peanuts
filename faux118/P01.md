# Faux118 P01 — render pass batching A/B

This is a Peanuts configuration candidate, not a modified driver. Keep the exact working Faux123 v1.1.8 package.

Baseline from the supplied ordinary gameplay run (last 12 pace windows): median FPS 6.7, GPU p50 178.75 ms, recording 23.55 ms, recording CPU 18.05 ms, draws 1289.5. The last cumulative pipeline summary reports 656 graphics and 6 compute, zero failures and 21 skipped draws while waiting. This makes persistent asynchronous pipeline starvation an unlikely sole explanation for sustained low FPS. It does not exclude stale compute outputs or a rendering defect. GPU clocks were not readable. These are aggregate non-identifying observations, not a published log.

Candidate: DM_VK_CHUNK_PASS=600 (only this change). The pinned Peanuts documentation identifies 150 as the current default and 600 as the previous default. Larger chunks may reduce pass splitting and associated tile stores/loads on a tile-based GPU; they may instead increase latency or worsen overlap. No performance claim until matched A/B testing. Do not alter DM_VK_CHUNK, disable barriers, or raise GPU clock limits. Remove the candidate if any visual error, crash or regression appears.

Priority remains a short DM_VK_NANSCAN=1 combat diagnostic separately, followed by ordinary A/B runs. Do not use diagnostic FPS as benchmark data.
